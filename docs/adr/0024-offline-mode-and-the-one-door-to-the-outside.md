# 0024. Offline mode and the one door to the outside

- Status: Accepted, amended by [0025](0025-update-file-upload.md)
- Date: 17/11/2026
- Amends: [0014](0014-https-and-certificates.md) (a public name can no longer stay while the box is offline; leaving it is a step of switching offline mode on), [0018](0018-path-to-0-1.md) (auto-update stops with offline mode; the host script reads one more key), [0012](0012-calendar-sync.md) (calendar sync pauses instead of failing when its connection is off)

## Context

Families who keep the box in the home network expect it to stay there. The product owner decided (Q62 b, 16/11/2026; Q141 to Q146, Q154, 17/11/2026) that a household can switch **offline mode** on: the box then opens no connection to anything outside the home network, and shows proof of it. Before this ticket six parts of the box went outside on their own (weather, calendar sync, ICS feeds, web images, the DNS service with its certificate authority, and the update check of the host script), each with its own HTTP client, so no single place could stop or even list them.

## Decision

- **One door.** Package `internal/outbound` is the only place that makes a connection to the outside. Code takes a client per connection from a `Gate` (`Client(service, timeout)`, `NewClient` for special cases, `Check` for work that is not an HTTP request). Before every request, also every hop of a redirect, the Gate asks the switches: in offline mode or with that connection switched off it **refuses, records the attempt (time, connection, target host) and never opens a socket**; when a request goes through it records the **last contact**. A database that cannot be read refuses (fail closed). `outbound.Local` is the client for the home network (the kiosk app on a display, the box itself): it refuses any address outside private, loopback and link-local ranges.
- **A check that nothing goes around it.** `internal/outbound/bypass_test.go` parses every Go file of the box and fails on `http.Get`, `http.DefaultClient`, a hand-made `http.Client`, `http.Transport`, `net.Dial`, `net.Dialer`, name lookups in `net` and `crypto/tls.Dial` anywhere but package `outbound`, and on importing libraries that open connections of their own (`miekg/dns`, CertMagic, ACMEz, libdns, `net/smtp`) anywhere but `internal/publiccert`. Tests, `tools/` and the benchmark tool are exempt. In production `outbound.InstallDefault` also gates `http.DefaultTransport`, so a library that falls back to the default client is stopped and listed as "other" (or as its connection, when the request context names it).
- **The reverse lookup of the box's own address** (the router name of ADR 0014, Q92) goes through `outbound.HomeResolver`, which answers only for addresses of the home network and refuses any other before a request goes out. The server does not use `net.DefaultResolver` itself, so the bypass check needs no exemption for it. Names ending in `.home` and `.internal` count as home names besides `.local`, `.lan`, `.home.arpa` and `.fritz.box`.
- **The DNS service** (libdns providers, CertMagic, the ACME order, ZeroSSL account keys) is covered at the point of its operations: every provider call passes the Gate, `Setup` is refused first, and the DNS service never runs while offline mode is on, because switching offline mode on with a public name is only possible together with leaving the name (below). The libraries' own sockets (ACME, DNS propagation checks) cannot be wrapped, which is why the import check keeps them inside `internal/publiccert`.
- **The connections** (the page "Connections to the outside", `/settings/connections`, parents only): weather, update check, calendar services, ICS subscriptions, recipe import (the switch exists; the feature is version 0.3), web images, and the DNS service (no switch of its own). Place search is not one: the list of places is on the box (ADR 0023). Offline mode is one more switch above them. The single switches are **kept** while offline mode is on, so switching it off brings them back as they were; a box set up offline in the wizard has no earlier state, so every switch comes back on.
- **State is the box's, not a household's** (`outbound_box`, `outbound_service`, `outbound_contact`, `outbound_refused`): the Gate must work before the first household exists, because the wizard asks "Should the box stay fully offline?" right after "Only in the home network" (Q142) and a public name needs the internet. Going back to choose a public name takes the answer back. The refused attempts keep the latest 200.
- **Paused, not failed.** A calendar whose connection is off keeps its events and shows the word tag "paused, offline mode"; the scheduler does not try it, a manual sync is refused and recorded without touching the sync state, queued changes stay queued, and the stale-sync warning ignores it. Switching off resumes at the next scheduler tick.
- **A public name** (Q143): offline mode can only be switched on after changing to "Only in the home network". The page "Switch on offline mode" shows what this costs (a new address, every device by name trusts the box again, passkeys are bound to the old name) and does the steps in order: delete the DNS records at the service (preselected, the last connection), forget the public name, make a new CA (`pki.Reprovision`: the standby CA of a public name is limited to that name and cannot vouch for the address at home), switch on. If the service refuses to delete, nothing is changed.
- **Updates** (Q145): the host script reads `offline=yes` from the `update-settings` file (a fixed key; any other line, a link or a doubtful file means online) and contacts nothing. The box writes it while offline mode is on or the update check is switched off, and omits the line otherwise, so the file is the old one. The script records `checked=<RFC 3339>` in the status file whenever it looked at the release feed; that is the last contact of the update check. After 90 days (7 to 365, set on the page) without an update parents see a reminder with a link to the install guide chapter "Update without the internet". The date counts from the install or the last `updated` report. Uploading an update file in the web interface is [ADR 0025](0025-update-file-upload.md) (Q154); the guide keeps the manual way for a box without the install script.
- **Honest scope** (Q146): offline mode covers the box itself. The host system may still sync the time (NTP) and fetch its own updates, and an AI assistant in the home network can carry what it reads out of the house; the page says so and the guide shows how to take the time from the router. Pages and displays load nothing from outside (a test checks the pages' markup).
- **API** (ADR 0015 parity): `GET /outbound`, `PATCH /outbound` (offline, single switches, reminder days; 409 while locked or with a public name), `POST /outbound/offline` (the change with a public name; 502 and nothing changed if the DNS service refuses). Requests that need a connection that is off are answered with 409.

## Consequences

- A new outbound feature takes a client from the Gate and gets a switch on the page; the bypass test fails otherwise.
- The recipe import (0.3) and Outlook (#177) must use the Gate. The `recipes` service is already listed and switchable.
- Switching offline mode on with a public name is a one-way trip for devices: every device has to trust the box again, and passkeys of the old name stop working.
- While offline, weather chips fade after their maximum age and the box shows no weather.
